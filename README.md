# Padel

Native iOS + Apple Watch padel scoring app with Americano/Mexicano tournament support and TestFlight deployment through GitHub Actions.

## Architecture

```
Padel/
├── Packages/PadelKit/        Swift package: scoring/tournament logic
├── iOS/PadelApp/             SwiftUI iOS app
├── WatchApp/PadelWatch/      SwiftUI watchOS app
├── Config/App.xcconfig       Local-development fallback identity
├── project.yml               XcodeGen specification
├── fastlane/                 TestFlight deployment
└── .github/workflows/        CI + TestFlight deployment
```

The `.xcodeproj` is generated by XcodeGen. For CI/TestFlight, all Apple credentials and app identity are configured in one place on GitHub:

**Settings → Secrets and variables → Actions**

# TestFlight setup from Windows

The setup is designed for Windows + browser. No local Mac, exported `.p12`, certificate password, Fastlane Match repository, or manually stored provisioning profile is required.

## 1 — Open the central configuration page

In this repository open:

**Settings → Secrets and variables → Actions**

Use the **Secrets** tab for private credentials and the **Variables** tab for non-secret Apple/app configuration.

## 2 — Add the three Secrets

Create exactly these deployment secrets:

### `APP_STORE_CONNECT_KEY_ID`

Find it in App Store Connect:

https://appstoreconnect.apple.com/access/integrations/api

Go to **Users and Access → Integrations → App Store Connect API → Team Keys**.

Example:

```
2X9R4HXF34
```

Check: it is the Key ID (not Team ID), normally 10 characters, and normally appears in the downloaded filename `AuthKey_<KEY_ID>.p8`.

### `APP_STORE_CONNECT_ISSUER_ID`

Copy the Issuer ID from the same App Store Connect integration page.

Example:

```
57246542-96fe-1a63-e053-0824d011072a
```

Check: UUID format, 36 characters including four hyphens.

### `APP_STORE_CONNECT_API_KEY_P8_CONTENT`

This Secret contains the **original contents** of the Apple `.p8` file. **No Base64 conversion is needed**.

Open the `AuthKey_<KEY_ID>.p8` file in a text viewer (for example a file preview/text editor on iPhone), select **all** the contents, and copy everything, including the first and last lines:

```text
-----BEGIN PRIVATE KEY-----
MIGTAgEAMBMGByqGSM49AgEGCCqGSM49AwEHBH...
-----END PRIVATE KEY-----
```

The example above is incomplete and must **not** be used as the actual Secret. A real key has many more characters between the markers.

Open [Padel → GitHub repository Secrets](https://github.com/NicolajWH/Padel/settings/secrets/actions), select **New repository secret**, enter the name `APP_STORE_CONNECT_API_KEY_P8_CONTENT`, and paste the complete multi-line text into **Secret**. GitHub accepts multi-line Secrets, so retain all line breaks and both BEGIN/END lines. Press **Add secret**.

This can be done entirely on **iPhone**, provided you have access to the previously downloaded `.p8` file and a text viewer. Apple permits a private key download only once; if the file is lost, generate a new Team API key and update its corresponding Key ID.

**Security:** Treat the `.p8` private key as a password. Do not commit it, send it in chat, or upload it to a converter website. Base64 is not encryption and is not required for GitHub Secrets.

## 3 — Add the seven Variables

On the same GitHub page select **Variables → New repository variable** and create:

| Variable | Padel value | What it controls |
|---|---|---|
| `APPLE_TEAM_ID` | `77GX5T6B82` | Apple Developer Team |
| `APP_DISPLAY_NAME` | `Padel` | Display name |
| `APP_BUNDLE_IDENTIFIER` | `com.worsa.padel` | Main iPhone app |
| `WATCH_APP_BUNDLE_IDENTIFIER` | `com.worsa.padel.watchapp` | Watch app |
| `WIDGET_BUNDLE_IDENTIFIER` | `com.worsa.padel.widgets` | iPhone widgets |
| `WATCH_WIDGET_BUNDLE_IDENTIFIER` | `com.worsa.padel.watchapp.widgets` | Watch widgets |
| `ICLOUD_CONTAINER_IDENTIFIER` | `iCloud.com.worsa.padel` | CloudKit container |

These Variables are the source of truth for GitHub/TestFlight deployment. `Config/App.xcconfig` contains local-development fallback values only; CI overrides them.

## 4 — Check Apple-side identifiers

The following explicit App IDs must exist in Apple Developer and match the GitHub Variables exactly:

```
com.worsa.padel
com.worsa.padel.watchapp
com.worsa.padel.widgets
com.worsa.padel.watchapp.widgets
```

HealthKit must be enabled for the iPhone and Watch App IDs. The iPhone App ID uses iCloud/CloudKit with:

```
iCloud.com.worsa.padel
```

The App Store Connect app record must use the main Bundle ID:

```
com.worsa.padel
```

## 5 — Final GitHub checklist

Under **Settings → Secrets and variables → Actions**, verify:

**Repository secrets (3)**

```
APP_STORE_CONNECT_KEY_ID
APP_STORE_CONNECT_ISSUER_ID
APP_STORE_CONNECT_API_KEY_P8_CONTENT
```

**Repository variables (7)**

```
APPLE_TEAM_ID
APP_DISPLAY_NAME
APP_BUNDLE_IDENTIFIER
WATCH_APP_BUNDLE_IDENTIFIER
WIDGET_BUNDLE_IDENTIFIER
WATCH_WIDGET_BUNDLE_IDENTIFIER
ICLOUD_CONTAINER_IDENTIFIER
```

The following older Secrets are not used by the new workflow:

```
APP_STORE_CONNECT_API_KEY_BASE64
IOS_DISTRIBUTION_CERTIFICATE_BASE64
IOS_DISTRIBUTION_CERTIFICATE_PASSWORD
MATCH_PASSWORD
MATCH_GIT_BASIC_AUTHORIZATION
```

## 6 — Deploy to TestFlight

Open:

**Actions → Deploy to TestFlight → Run workflow → Run workflow**

The workflow:

1. Runs PadelKit unit tests.
2. Validates all 3 Secrets and 7 Variables before deployment.
3. Generates app icons and the Xcode project.
4. Writes the raw `.p8` content to a temporary file on the macOS runner and checks its format.
5. Passes Team ID, display name, all Bundle IDs and the iCloud container from GitHub Variables to Xcode.
6. Uses automatic/cloud-managed signing with `-allowProvisioningUpdates`.
7. Builds the Release archive and uploads it to TestFlight.
8. Deletes the temporary API-key file.

The workflow also runs automatically on pushes to `main`.

## Reusing this repository for another app

When this repository is copied for a new app, the deployment configuration is intentionally concentrated on one GitHub page. Add the 3 Secrets, change the 7 Variables, create matching Apple identifiers/App Store Connect records, and review capabilities/entitlements if the new app needs different Apple services.

For local Mac development, `Config/App.xcconfig` provides fallback app-identity values. GitHub Actions does not treat those fallback values as the deployment source of truth.

## Verify a new TestFlight deployment

After creating or resetting GitHub Secrets or Variables, open:

https://github.com/NicolajWH/Padel/actions/workflows/testflight.yml

Choose **Run workflow** on `main`, or push a new commit to `main`. Changes to repository Secrets/Variables alone do not automatically start a workflow.

First check **Validate deployment configuration**. If it reports a missing name, add that name under **Settings → Secrets and variables → Actions** (Secrets or Variables as indicated). Once validation passes, inspect **Build and upload to TestFlight**. A green workflow indicates the upload step completed; the build still needs to finish processing in App Store Connect before it is available to testers. Never paste a private `.p8` key into an issue or Actions log.
